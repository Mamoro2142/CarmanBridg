# Карман · независимое приложение бюджета для Android

**Версия 1.0.0 / versionCode 1 / пакет `com.mamoro.karman` / Android 8.0–15+ (minSdk 26, compile/targetSdk 35).**

Это **новое приложение**, а не обновление `com.koshelek.app`. Оно устанавливается рядом с прежним «Кошельком». Android не допускает обновление APK другого `applicationId`, даже с тем же названием. При обновлении самого «Кармана» используйте **прежний приватный ключ подписи**, а также увеличивайте versionCode.

## Главный сценарий

Нажать `+` → ввести сумму → выбрать категорию → **Сохранить**. Сегодняшняя дата и последний использованный счёт подставляются автоматически. В форме видны основные категории, а заметки, смена даты и шаблон — только под «Дополнительно». Ввод `01`, `1000.5` и `1 000,50` нормализуется; сумма хранится в минимальных денежных единицах, без `Double`.

Шаблон **с фиксированной суммой** можно провести одним нажатием на главной. Шаблон без суммы открывает заполненную форму. Для защиты от случайного списания исправление обычной операции поддерживается через историю (дата, категория, заметка; сумму нужно удалить и ввести заново).

## Что входит в первую самостоятельную версию

- 5 вкладок: Главная, История, План, Счета, Ещё; свайп между вкладками, быстрый прямой переход по нажатию, системная «Назад» не закрывает приложение на главной.
- Локальное хранение SQLite, операции дохода, расхода и перевода, счета RUB / USD / EUR / BYN; ручная настройка новых курсов.
- **Основной рублёвый баланс** — зафиксированные исходные рублёвые суммы (на дату операций) и начальные суммы. По выбору пользователя к денежной части один раз добавляется текущая рыночная оценка инвестиций. Изменение курса/валюты **только отображает** конвертацию; исходный рублёвый баланс не меняется.
- Ручная настройка отображения общего баланса в ₽ / $ / € / BYN, плавная смена отображаемого числа.
- Бюджеты по категориям; месячные доходы и расходы; список и группировка расходов по категориям.
- Цели и резерв, планы платежей/подписок, ежемесячные и еженедельные повторы, ручное и автоматическое проведение при открытии/возвращении в приложение, защита от дублей.
- Отдельные инвестиции: облигации, номинал, текущая оценка, купонная доходность, покупки отдельными лотами, продажа с **FIFO**, комиссия покупки/продажи, календарь купонов и ручное зачисление купона.
- Резервный остаток с отдельными суммами: цели + дополнительный резерв − ручное перекрытие; платежи следующего месяца − ручное покрытие резервом.
- Локальный экспорт и импорт собственного формата JSON через системный файловый выбор; подтверждение перед заменой данных.
- Дизайн: минималистичный графит, сдержанный янтарный акцент, крупные числа и кнопки, без визуального «снега» по умолчанию.
- Не запрашивает интернет и не отправляет данные на сервер. Нет сторонних SDK аналитики и рекламы.

### Пример облигации

Покупка 1 бумаги по 950 ₽ + покупка 5 бумаг по 750 ₽: **6 бумаг, вложено 4 700 ₽** (без комиссии). При номинале 1 000 ₽ номинальная сумма равна **6 000 ₽**. Если рыночная цена введена 1 000 ₽, оценка позиции 6 000 ₽. Покупки списывают реальные деньги со счёта. Рыночная оценка добавляется к общему балансу только при включённом переключателе и ровно один раз, доступный денежный остаток от этого не меняется.

## Бухгалтерские правила

- Баланс в рублях — **исторический**: операции в других валютах фиксируются в рублёвом эквиваленте в момент ввода; обновление ставок не переписывает историю.
- Перевод между счетами **не создаёт рублёвых денег**: рублёвая оценка у списания и зачисления одинаковая. Реальная сумма зачисления в другой валюте задаётся явно либо вычисляется по установленному курсу.
- В инвестициях текущая стоимость актива отличается от денежных счетов. Вложенная себестоимость отслеживается отдельно от номинала и оценки. Процент купонной доходности вводится вручную; сам по себе баланс не меняет.
- Бюджетные расходы не включают переводы и покупки ценных бумаг. Выплаченный купон учитывается доходом; денежные остатки меняются только при реальной операции.
- При отсутствии интернета никаких валютных обновлений не происходит. **Справочные курсы сейчас только ручные**; онлайн-курсы и исторические котировки — в списке следующего этапа.

## Ограничения версии 1.0.0

Это **первая функциональная сборка нового проекта**, не 1:1 замена всех возможностей прежнего «Кошелька» 1.11.2. Следующие направления указаны в `ROADMAP-22.md`: автоматическая загрузка курсов и котировок, полноценный редактор всех полей операции, фото чеков и OCR, долговые инструменты, CSV, расширенная аналитика, синхронизация, комплексная инвестиционная отчетность, анимация прокрутки цифр и опциональный сезонный дизайн. Старые данные не импортируются автоматически: новый пакет и собственная БД, свой JSON-формат резервной копии. **Не удаляйте старое приложение**.

Приватные ключи и пароли не входят в исходники. Резервные JSON-файлы не зашифрованы; храните их как конфиденциальную финансовую информацию.

## Компиляция GitHub Actions

В проекте `.github/workflows/android.yml`. Проходит `testDebugUnitTest`, `lintDebug`, `assembleDebug`, затем при наличии четырёх GitHub Secrets собирает подписанный `assembleRelease`. APK появляется в разделе **Actions → нужный запуск → Artifacts**. Устанавливайте **`Karman-1.0.0-RELEASE-signed`**, не DEBUG, если хотите обновляться поверх версии 1.0.0 в дальнейшем.

- `KARMAN_KEYSTORE_BASE64` — base64 файла .p12.
- `KARMAN_STORE_PASSWORD` — пароль контейнера.
- `KARMAN_KEY_PASSWORD` — пароль ключа.
- `KARMAN_KEY_ALIAS` — `karman-release`.

Папка ключей передаётся отдельно в `Karman-PRIVATE-signing.zip`. **Никогда не добавляйте её в GitHub**, даже в приватный репозиторий. Создайте secrets через GitHub → репозиторий → Settings → Secrets and variables → Actions.

### Развёртывание только с телефона

Можно создать **новый репозиторий** `Karman` на GitHub, загрузить в его корень **`Karman-1.0.0-source.zip`**, а `.github/workflows/android.yml` создать отдельно. Workflow сам распакует архив исходников, если в репозитории нет `settings.gradle.kts`. Это запасной способ для телефона; предпочтительнее распаковать файлы и хранить **полный исходный код отдельными файлами** в GitHub.

**Важно:** если в репозитории лежит только ZIP, Github не показывает его содержимое и не сможет делать нормальный построчный diff. Для будущей разработки предпочтительно перенести файлы в папки репозитория. Создание нового удалённого репозитория и первый запуск Actions здесь **не выполнялись**.

## Проверки и ограничения окружения

Проверена компиляция независимого Kotlin-модуля расчётов (`Models.kt` + `LedgerMath.kt`) с `kotlinc`. Android SDK и Gradle-плагины недоступны в текущем рабочем окружении, поэтому **успешная APK-сборка и запуск на устройстве здесь не подтверждены**. GitHub Actions содержит автоматизированные тесты SQLite и расчётов; итоговый статус появится после запуска в репозитории. Проверка на реальном Android-устройстве необходима.

## Обновление следующих версий

Для каждой следующей версии увеличивайте `versionCode` на 1, обновляйте `versionName`, используйте неизменные `applicationId` и ключ подписи. Вносите одно исправление — один отдельный Git-коммит; фиксируйте в `CHANGELOG.md`, затем выполняйте сборку и тесты.
